# 决策记录：测试简报固定模板与 skill 方案

- **日期**：2026-08-18
- **状态**：已实施
- **参与人**：用户、AI 智能体（Codex）

## 背景与问题
日报、周报、测试进度此前按对话中的固定结构临时生成，项目内没有可直接复用和校验的模板文件。用户希望把三类简报也固化为固定模板，并确认后续自动化任务使用 skill 是否更合适。

## 决策
1. 固化日报、周报、测试进度三份 Markdown 模板，存放于 `docs/templates/`，统一使用 `{{...}}` 占位符，固定 9 类设备清单与章节结构。
2. 创建并安装 `emergency-test-reports` skill，安装在 `~/.codex/skills/`，包含模板资产、字段说明、数据来源优先级、输出格式与脱敏要求，供 Codex 对话中自动生成三类简报。
3. skill 源文件保存在项目内 `docs/skill-src/emergency-test-reports/`，通过 `scripts/install_emergency_test_reports_skill.py` 一键安装，便于后续修改和重复部署。

## 自动化任务形态
- 对话式自动生成：由用户直接说“生成日报/周报/测试进度”，skill 负责选模板、提取数据、填写、转换与安全校验。
- 定时无人值守：仍需要本地 Python 脚本和系统调度（cron 等）承接；skill 可作为生成流程规范，脚本可按相同模板和口径实现。
- 结论：两者互补，后续阶段 C 自动化先以 skill 固化流程，再视需要增加定时执行脚本。

## 影响评估
- 模板与 skill 均不包含联系人、电话等涉密字段；正式测试报告 docx 模板仍按项目规范置于 `sources/`，不入 Git。
- 版本号由 0.6.0 升至 0.7.0。
