# 文件夹结构设计说明

- **编写日期**：2026-08-11
- **状态**：有效

## 设计原则

1. **职责分离**：源码、数据、输入、输出、文档互不混杂，每个目录只承担一类职责。
2. **输入/输出分界**：`sources/`（原始资料输入）与 `reports/`（导出与生成成果）严格分开，便于增量导入、成果追溯与清理。
3. **演进预留**：目录结构为阶段 B（测试回传对账）、阶段 C（报告生成）、阶段 D（外部 AI）、阶段 E（内网 Web）预留清晰落点；`equipment/` 保持为纯数据层，未来可被 Web 或外部 AI 复用。
4. **安全边界**：本地数据库、原始台账、导出成果均不进入 Git 仓库；涉密数据只在本机流转。

## 目录职责与演进落点

| 目录 | 职责 | 演进预留 |
|---|---|---|
| `equipment/` | 阶段 A 核心：导入、归一化、查询、导出 | 阶段 D/E 作为数据层被 Web 或外部 AI 调用 |
| `data/` | SQLite 全量数据库，Schema 已预留测试状态字段 | 阶段 B 直接更新状态字段 |
| `sources/设备台账/` | 原始分类台账与全量汇总表 | 后续新设备类型直接放入对应文件 |
| `sources/测试报告/`、`sources/进度资料/` | 历史报告与进度文件存档 | 阶段 B/C 对账与报告生成的参考基准 |
| `reports/` | CLI 导出 Excel、阶段 C 生成的测试报告 | 阶段 C 报告统一输出至此 |
| `scripts/` | 辅助脚本 | 阶段 B 对账脚本、阶段 C 报告生成脚本 |
| `tests/` | 单元测试 | 随功能新增同步补充 |
| `docs/` | 面向用户与开发者的公开文档，含固定模板与 skill 源码 | 使用手册、接口说明、报告模板维护 |
| `.project/` | 项目对齐系统（智能体协作） | 决策、计划、日志持续更新 |

## 历史遗留说明

- 早期版本中 `全设备台账/`、测试报告、进度文件散落在根目录，本次已统一收纳至 `sources/` 对应子目录。
- `全量设备.xlsx` 为 9 类脱敏分类台账的整合产物，与分类表同放于 `sources/设备台账/`，便于比对。
- 数据库内 `source_file` 字段保留的是导入时的原始文件路径，仅作追溯用途，不随目录调整改写。
