# 应急通信测试简报固定模板说明

## 模板清单

- 日报：[通信测试日报模板.md](templates/通信测试日报模板.md)
- 周报：[通信测试周报模板.md](templates/通信测试周报模板.md)
- 测试进度：[测试进度模板.md](templates/测试进度模板.md)
- 正式测试报告（docx）：`sources/测试报告/应急通信装备测试报告模板.docx`

三份模板均采用 Markdown，`{{...}}` 即待填字段，填写完成后替换为实际内容。

## 各模板用途

| 模板 | 适用场景 | 内容定位 |
| --- | --- | --- |
| 日报 | 单个测试区域当天或某份报告更新时 | 按 9 类设备逐项列明测试数、正常数、异常原因和待跟进事项 |
| 周报 | 一周测试完成后 | 汇总本周涉及区域、逐设备统计、每日记录、本周小结和下周计划 |
| 测试进度 | 某一轮次测试推进到一定阶段 | 汇总各区归档状态、分类进度、本周更新和待闭环事项 |

## 固定设备类别

日报、周报统一保留 9 类设备，无此类设备或未测试时填 `0` 或“未测试”：

1. 卫星电话（含固移）
2. 370MHz 手台
3. 北斗终端
4. 无人机
5. 单兵图传
6. 布控球
7. 卫星便携站
8. 应急通信指挥车
9. 视频会议系统

测试进度的分类进度表保留 5 类既有口径（卫星电话含固移、370MHz 手台、布控球、无人机、通信指挥车），如某轮新增其他设备口径，可在表内追加对应行。

## 数据来源与口径

数据来源优先级如下：

1. 各区正式测试报告（docx）
2. `sources/进度资料/通信设备日周报.txt`
3. `sources/进度资料/各区测试进度.txt`
4. 《应急装备数量统计（内部）》基准表

数量口径冲突时，以《应急装备数量统计（内部）》基准表及 `.project/decision-log/` 中已确认口径为准；报告本身存在测试数、正常数和异常数不一致时，须在日报“说明”或“待跟进事项”中显式标注。

## 使用与输出

- 日报、周报、测试进度生成后建议输出至 `reports/测试报告/`，按现有习惯也可暂存 `sources/测试报告/生成/`。
- 需要微信发送时，将 Markdown 转成纯文本 TXT（去掉表格符号）或 PDF，文件命名沿用现有习惯，例如 `日报_东丽区_2026-08-12.md`、`周报_2026-08-10至2026-08-16.md`、`测试进度_第三轮_2026-08-12.md`。
- 修改模板后，应同步更新 `docs/templates/` 与 `docs/skill-src/emergency-test-reports/assets/templates/`，保持两者一致。

## 配套 skill

项目已提供 `emergency-test-reports` skill，源文件在 `docs/skill-src/emergency-test-reports/`，已安装至 `~/.codex/skills/emergency-test-reports/`。对话中说“帮我生成日报/周报/测试进度”即可触发，skill 会按上述模板、数据来源和口径自动完成填表、输出与安全检查。修改源文件后运行以下命令重新安装：

```bash
python3 scripts/install_emergency_test_reports_skill.py
```

## 安全提示

填写过程中不录入联系人电话等涉密字段；对外使用前先做脱敏检查。
